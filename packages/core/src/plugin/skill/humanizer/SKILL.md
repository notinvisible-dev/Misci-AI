Ghost Human

Catches the writing patterns that make text sound AI-generated, and fixes them. Based on Wikipedia's "Signs of AI writing" guide plus common LLM tics.

The tells, and the fix for each
Buzzword vocabulary — delve, tapestry, underscore, pivotal, crucial, foster, landscape, testament, encompassing, valuable insight, key turning point → Use plain, ordinary words instead.
Rule of threes — always exactly 3 adjectives/examples ("innovative, transformative, groundbreaking") → Vary the count. Sometimes 1 thing, sometimes 5.
Negative parallelism — "It's not X, it's Y." → State the thing directly, skip the contrast structure.
Em dash overkill — dashes used constantly, including just as a crutch, not only for "punchy emphasis" → Use commas or periods, or restructure the sentence.
Excessive bolding — bolding random words like a textbook → Bold rarely, only when it truly matters.
Weasel attributions — "industry experts say," "some critics argue," "observers have noted" with no real source → Name the actual source, or cut the claim.
Vague "from X to Y" phrasing — sounds broad, says nothing concrete → List actual specifics instead.
Leftover chatbot sign-offs — "I hope this helps!", "Let me know if you need anything else!" → Just end the answer. No sign-off needed.
Repetitive summary phrases — "In summary," "Overall," restating what was just said → Cut it entirely if already said once.
Rigid formulaic structure — every section same shape (intro/challenges/future/conclusion) → Let structure follow the actual content.
Superficial/vague analysis — sounds smart, says nothing concrete → Use real numbers, names, specifics.
Mechanical emoji use — emojis dropped into headers/lists on autopilot → Only use them if they actually fit the moment.
Hedge-stacking — "It's important to note that...", "It's worth mentioning..." → Just say the thing.
Corporate-safe non-opinions — refusing to commit to a real stance, over-balancing everything → Take an actual position where one is warranted.
Over-summarizing before answering — recapping the question back before responding → Skip straight to the answer.
Fake enthusiasm — "Great question!", "I'd be happy to help!" → Cut the enthusiasm, just help.
Listy overkill — turning a simple answer into bullets/headers when it didn't need it → Use plain prose for simple answers.
Vague transitions — "That said...", "With that in mind...", "Moving forward..." → Cut, or use a natural connector.
Over-qualifying — stacking "may vary," "it depends," "in some cases" together → Pick one qualifier, or none.
Symmetrical structure — every pro has a matching con, every point identical length → Let points be uneven lengths, naturally.
Closing summary paragraphs — restating the whole answer in a "wrap-up" → End after the last real point.
Robotic over-politeness — excessive "certainly," "of course," "I understand" → Drop it, respond plainly.
No personality — no contractions, no casual voice, too clean → Use contractions, natural phrasing, a bit of voice.
Vague AI-summary phrasing — "one big problem," "a real issue," empty summarizing instead of a specific detail → Say the actual specific thing.
Forced casual voice — tossing in "kinda," slangy asides that feel bolted-on rather than natural → Only use casual words where they'd actually occur naturally, not as a "sound human" trick.
Neat little wrap-up line at the end — a tidy, quotable closing sentence ("Some things take longer than X to fix") → End on an actual moment or action instead, no moral-of-the-story line.
Citations/links dropped mid-narrative — breaks flow in fiction/story writing → Keep sourcing separate from the story itself, or leave it out of creative text entirely.
How to apply this

When editing text: scan for these patterns one at a time, flag or fix each instance found, and don't introduce new ones while fixing (e.g. don't replace one em dash with three more em dashes).

When writing fresh: keep it short, direct, and varied in rhythm. Skip sign-offs and hedges. Commit to real specifics over vague broad claims.

When reviewing code comments/docs: same rules apply — watch especially for buzzword vocabulary (item 1) and over-formulaic structure (item 10) creeping into README files and comments.

This does NOT apply on visuals, only on text.
